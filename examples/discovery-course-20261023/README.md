## 每关保存与检查

`build.mjs`保留人工布局与设计假说；`levels/<稳定ID>/`保留原图、来源、真实动作证书和物理QA，修改版本不覆盖原件。`course-order.json`只列当前试玩流程，ID不随顺序变化。`sync-site.mjs`只输出入口，不把答案、规则结论或设计意图放到试玩页。

地图、回放、求解与验收均使用同级本体唯一引擎。合法性、全部最优无非致死重合、去终点安全、编号无关和码往返负责排除物理问题，不能作为趣味评分。当前是独立关卡，不声称整图接入已经验证。

## 当前范围与验收限制

现为7关的重排版本，6张课程专用图、1张既有图的复用或课程变式。前三关只使用墙、鬼与目标，分别处理引离、停位和两个威胁的共同局面。第四关才加入普通门，并把它放进先引出守卫再从另一入口返回的完整问题。第五关继续使用门与鬼，先安排妨碍接近的另一只鬼，再处理目标守卫；不是马上换字母机关和钥匙数字。第六关把单组字母机关放进先安排守卫再开路的谜题，删去了旧稿同时出现的钥匙与数字门。第七关接回《错位》的用户优化版，在同一类字母机关中改变操作用途；不先用演示关揭示它的关键发现。其余完整谜题保留为候选，没有从本体地图集删除。

旧31关中连续的移动、钥匙、单个按钮、门型对照、双鬼队列和争位展示不再串在流程里。退出的原图和证据仍保留，旧关序见[原发布版顺序](reviews/order-published-v1.json)。四份在反馈前已做的微型关压缩没有发布；不把整体反馈补写为逐图坏评。

## 为什么改变安排

[真实反馈与前后判断](reviews/teaching-feedback-20261023.json)：原先围绕逐条规则的可见证据组织关卡，导致机关连续换展，独立小关除了展示机制几乎没有问题可解。现在以玩家要解决的完整问题组织，同一组少数元件先支持不同的选择、停位和动线，再加入新元素。规则在游玩中被摸清，不要求逐条专门演示。

当前开场让玩家尝试引开目标守卫，再思考鬼停在哪里才能让真正通路空出来，随后同时安排两只鬼。原单环关03复盘后与开场仍是同一完整引鬼计划、只多了赶路，已退回候选，保留原件与先前判断。这里写的是设计预期，实际趣味仍需玩家反馈；唯一最优或必要事件不证明精妙。
