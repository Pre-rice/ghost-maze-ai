# 《迁居》：把上层守卫带下来，才有回去的路

2026-11-17。拟替换第48关未评价课程稿《同室两用》58，其[原图与原说明](old-course48-note.md)保留，不是原作等价精简；正式本体和地图集不改。17格，双鬼、两对楼梯、普通门、钥匙与目标1，15步唯一一类。没有字母、箭头或玻璃。人读结论仍待未知规则真人审查。

## 完整问题与设计关键

钥匙与目标在楼上两端，目标前守卫会先靠近左梯，不能直接穿过去。预期先让楼下鬼停在左梯，离开上层楼梯时借上鬼挡住它，自己去右侧取物。把上鬼带下右梯，利用隔墙转角与普通门留到下道，再回左梯：原下鬼追到上层，两只实际交换楼层，目标接近才空出来。

熟悉的“先把一只彻底安置好”在这里有具体矛盾。把下鬼留在门左(2,3)，会堵住后来进左梯的接近；留在门右(3,3)，从右梯下来后它会抢先堵住转弯。两种走法都有安全前缀，不依赖编号或隐藏边界。正确计划暂不把下鬼处理完，门后泊位要留给来自楼上的那一只。

当前六句卡见[来源](../../levels/74/source.json)。它接在桥后：桥把一只留上层，本题两只实际换层；后面的留层又可各留原层。不是迁层越多越好，也不按步数排难度。

## 怎样取舍

[15格机械核](construction.json)先手动完整走通，再复验原生唯一15步。它太容易沿安全方向执行，所以没有直接递补。下层加左侧两格后，[17格无资源稿](expanded-construction.json)允许先安置下鬼的完整合理尝试，却也有19步不实际互挡、逐只处理的清洁方案，不能将两鬼交换说成全解必要。只加其中一格的两份16格稿均未选。

于是从任务本身要求先到右上取物，再回左上目标：[完整任务](complete-task.json)把钥匙放(4,2)，目标前放1。最优15步不变，旧19步逐只走法尚未取物便到了目标侧，完整续解无解；这不是用增加物件或解长证明趣味。当前上鬼第7步真下楼、下鬼第13步真上楼，第3步有实际跨层阻挡。

八个固定合法非实体、非楼梯单删中，六个无解；删下层左任一格仍同15步，但会移除那种合理的早期安置与绕探，故保留这两个格。不声称全局最小。移除任一鬼可13步、普通门改空有同15步最优重合、去内墙或任一楼梯对均无解；消融不是原图事件禁止，不能混写必要性。

## 验收与限度

[七项完整历史](complete-task.json)在允许／排除非最优重合两范围均穷尽无解：没有实际互相影响、上鬼从不到楼下、下鬼从不到楼上、两鬼从不共同在楼下、上鬼不到下层(3,3)、终局没有交换楼层、第一次从右梯上楼。临时给来源标记，两角色位置与旗标都进入完整监视键，实际物理另过当前所在层的全排列和全局换编号。

全部最优无伤、无复活、无重合，去终点安全；地图与回放码往返、冷开局、原生／快速最优一致。真正从下侧外格走一步进入，零钥匙无区外鬼，108态535后继含死亡一致，只声明这条入场条件。

`L U`两步、`U L D R R`五步及另一种旧安置九步安全但无续解；左探一步、上后左探、右探三步可17／19／21步清洁恢复。四条死亡与四个无效输入见[economy.json](economy.json)。
