# 跨层运送不自动产生合作

`small-ring.json`冻结四个短环试构。29步、37步稿的上层鬼在完整参考中一直不动；另两稿无解。短环的右中守卫从两端被看见时已经相邻，会当步抓到玩家，不能把它当作可以从远端安全引动的守卫。它们都未接入课程。

`taller.json`拉开上层安全接近空间后，守卫能真正移动，分别33／35／35步。但全都保留同最优的无相互阻路通关：先把下层鬼搬走留下，取物后再独立引走上层鬼。原期待的运送者再成为帮手没有成立，因此仍不接入，不继续加门追回新意。

两份文件各存一份基图，其它图存明确路径的字段编辑；`verify-small.mjs`、`verify-taller.mjs`重建并只读核对原图查询与实际参考，不覆盖冻结原件。没有发布证书、网页试玩、真人评价或训练。

第一次的无相互阻路查询把层内编号误当作跨层唯一编号，曾得到假无解；[原错误输出与修正](invalid-query-summary.json)明确隔离。修正版在每一当前局面的克隆上临时唯一标记，先证明物理不变，再逐鬼移除其它鬼作一步对照，发现同最优的普通方案。该谓词对全部鬼对称，不跟踪来源历史，也不把标记写进物理规则；若以后查询来源角色历史，仍须加入完整状态键。主站与公开32关不变。

层内编号限制此前已写在方法的《隔岸》复盘，本轮是没有执行既有约定；修正版另加入无交会首步不能误报互动的检查，不能将这次修正包装成新机制发现。
