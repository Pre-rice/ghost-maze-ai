# 不把旧终局加上取物回程就当成进化

手工提案是把《调度》的旧终点改为任务点，再要求返回外围。先在原图去终点的真实推进中重放四条70步最优，到达原终点后均有10步无伤返回出生点。因此，简单追加旧终点钥匙和外部终点，并没有否定旧的完整调度方案；不能以流程更长宣称新认识。

随后试在原参考全部未经过的中心(3,3)放钥匙，外围(6,1)设新目标。中心实际上是活动格，四边原本都开放；初始草稿将其误当成封闭格的断言失败后已经纠正，没有更改原图补齐假设。保留的脚本只重新赋同一条空边，不改变中心结构。

中心单钥匙／出口1门稿穷尽无解；中心加旧终点双钥匙／出口2门稿也穷尽无解。各自去终点的完整无伤图为2653／3117态，中心及旧终点都能分别安全到达，但双钥匙稿最多只能带一把。这不能解释成中心本身不可到达，也不证明任何其它改稿无解。
