# 内部评审：两处环路如何共同改变通行条件

本文件含剧透，建议先试玩。本候选仍待用户确认，不预先称为精品。

## 来源与精简

使用固定随机种子 930261 在 5×5 活动区探索两只鬼、A/B 开关与门的位置组合。4 万个初始提案中，20,407 个取得解证书；经过解长、按钮次数与去鬼对照的粗筛，留下 6 个待审候选。粗筛只缩小人工阅读范围，不是质量函数。

最终选择索引 12579，依据具体的状态关系而非最长解。由助手删除一只不参与解法的鬼、七个不参与核心关系的活动格，保留 18 格。起点右侧改成玻璃，使鬼与终点立即可见；左侧普通门阻断这处观察窗对走廊追捕的额外影响。

仅加玻璃会改变鬼的视线并产生 17 步绕法，因此没有直接保留该版本；普通门隔离视线后重新验证全部证据。普通门不是新规则，仍采用原游戏玩家可过、鬼不能过且阻挡视线的语义。

探索脚本 [discover.mjs](discover.mjs) 保留原提案逻辑，输出在 Git 忽略目录 `runs/coupled-search`。其中历史随机排序不是均匀洗牌，不能据此报告地图空间的均匀采样率；确切提案复现依赖同一 Node/V8 行为。本次使用 Node 24.19.0。正式地图由明确坐标的 `coupledMap()` 构造，不依赖再次运行探索脚本。

## 核心关系

鬼守在出口走廊。A 同时开放出口入口及下侧通路；B 在上方小环路与下侧诱导口之间互补切换。

直接开 A 再靠近出口会撞上鬼。先配置 B、打开 A，还需要从下侧诱导口把鬼向下拉远，才能安全接近上方按钮。但鬼向下移动并不等于通关：玩家到上方时又会把鬼往回引，直接冲入口仍然被抓。

此时再次切换 B，恢复上方小环路，再借这条环路绕到鬼身后进入出口。上方绕行与下侧诱导不是两道独立题：共享 B 的互补门态，且第一次改变的鬼位置决定玩家能否进行第二次操作。

最短证书：

```text
LURRULLDDDLUDRRRLLLURUUURRULLDLURRRDR
```

其中按钮操作按字母为 B、A、B。T=37，L=34，体力初值仍为 100；没有收紧体力强迫唯一解。

## 已验证与未验证的结论

| 检查 | 结果及范围 |
| --- | --- |
| 最短动作数 | 原引擎 BFS 与紧凑 A* 均为 37 |
| 禁止 B→A→B 子序列 | 两个求解器均穷尽无解；只针对原图、当前体力、无伤无复活范围 |
| 禁止到下侧 (4,5) | 两个求解器均穷尽无解 |
| 禁止鬼到达 (4,4) 或 (2,1)，分别检查 | 两个求解器均穷尽无解 |
| 不走左上 (1,1) | 仍有 56 次动作的替代解；因此不宣称上方最短绕法是所有解必需的唯一路线 |
| 去鬼对照 | 13 次动作可达；这是另一张图，不是原图的必要性证明 |
| 起点信息 | 原引擎 seenCells 和浏览器截图都确认鬼与终点可见 |
| 终点提前判胜 | 移除终点后同一动作序列仍不死亡，最终玩家 (5,2)、鬼 (4,2) |
| 分享码 | 解码前后逐动作完整物理状态一致 |
| 浏览器 | 使用真实方向键无伤通关，移动数为 34 |

以下三条是设计者提出的“可能的直觉路线”，不是已观察到的人类行为：

1. 开 A，回到上方直接接近出口。
2. 先 B 后 A，但跳过下侧诱导，直接回到上方。
3. 完成第一次诱导，但到上方后不绕鬼，直接进出口走廊。

三条具体动作串都在原引擎中死亡，逐步证据已存档；它们的失败不能推广成所有类似策略均已证明失败。

起点可见危险不等于所有信息公平性已证明。玩家仍需探索门与按钮的对应关系；是否有合理线索、是否需要推理而非试错、绕行是否冗长，都留待真实试玩。不能因为本题比旧题步数多就奖励为更好玩。

## 验证与数据纪律

`node examples/coupled-singlelayer/build.mjs` 重建地图和证据，包含独立 BFS 对照；`npm test` 包含本题回归，全仓共 94 项通过。参考引擎与旧种子检查通过，原游戏和子模块保持原样。

当前 `humanPreference: null`，目标质量标记为 `awaiting_user_review`。所有改图归在 `dual-loop-relay-v1`；它与旧诱鬼家族共享基础思想，不能仅凭换了家族名就声称是独立概念的泛化测试。旧批次反馈文件没有改动。
