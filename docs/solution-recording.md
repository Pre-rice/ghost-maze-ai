# 解法录制与逐步回放

2026-09-30。用户指出真实解法可能与求解器证书不同，要求记录自己的路线。本功能部署在 AI 仓库的本地游戏服务中，原游戏仓库和固定子模块保持不变。

## 使用

运行 `npm run review`，然后在新游戏页打开任意合法分享码。右侧出现“解法录制”面板：

- 每次状态更新后保留当前路线；移动、按按钮、楼梯、死亡和复活都参与识别。
- 通关后自动保存到本机；也可以随时点“保存当前路线”。
- “导出 JSON”可导出当前路线；[回放页](http://127.0.0.1:4178/replay.html)可以导入、下载、逐步查看已保存录制。
- 按钮单独标为“按 A/B（原地推进一回合）”，同时显示玩家、鬼和门的变化。

正式录制保存在 `data/solutions/<id>.json`，被 Git 忽略；需要备份可使用导出/下载。回放在独立页面运行原版规则与渲染，不改变正在玩的另一局。服务端保存前重放全部动作并核对完整终局物理投影。

## 记录的准确边界

这是**当前保留分支的解法记录**，不是逐键监听器或完整试错时间线。它从控制器历史的相邻状态，尝试真实 U/R/D/L/STAIR/REVIVE 动作恢复可重放序列，因此不会遗漏原地按按钮产生的鬼移动。

撤销/回溯后保存的是当前分支；已经撤掉并裁掉的尝试、无效撞墙、按键间停顿不在记录里。没有据此推断思考用时。多种动作得到完全相同后态时，`ambiguities` 保留等价选项，不能伪称已知道玩家原始按键。

每条录制绑定完整分享码、固定规则与服务端计算的地图标识。这里的 `verified.mapId` 来自分享码解码后的 MapDefinition；早期原始 JSON 的 mapId 对未规范化字段敏感，不保证与此相同。对照旧样本时应重放其分享码并核对规则/物理数据，不凭文件名或压缩字符串猜测同图。

`cleanWin` 只有在实际胜利、全程无死亡无复活时为 true。含复活路线仍可保存查看，但不会冒充无伤证书。录制本身不等于人类质量标签；自动化测试录制只能写测试目录，不能混入真实解法训练数据。

本机录制同 ID 重试幂等，内容不同则拒绝覆盖。浏览器 localStorage 仅保留最近一次当前路线草稿，永久备份以服务端文件或下载文件为准。本版单条路线最多 2000 次有效动作。

旧页面不会因服务更新自动安装录制器。本次用户选择在新页重演。若以后确需保留仍在内存中的旧局，可由用户在该页面控制台执行 `import('/recorder.js')`；只恢复控制器尚保留的历史，不恢复已丢失的分支。不要为安装录制器擅自刷新用户未保存的旧局。

## 验证

101 项测试通过：恢复原地按钮动作、撤销分支、轨迹裁剪、死亡/复活、非法动作与终局篡改、幂等保存和 HTTP 入口均有回归。浏览器在独立端口 4181 自动化通关旧组合图和用户优化图，分别保存 37/40 次动作；测试文件位于 `runs/recorder-qa-solutions/`，不是真实用户轨迹。

回放第 27 步明确展示旧图中玩家 (4,1) 原地按 B，鬼从 (4,3) 到 (4,2)。这验证录制器能保存用户强调的节奏机制；它不证明用户实际走了这条自动化路线。
