# 小单元、反事实证据与编辑搜索

2026-09-29：已实现可运行的机制分析和有限编辑实验。当前输出是机制证据，**不是趣味评分，也不是训练完成的生成模型**。

## 必要性怎样证明

`src/design/analyze.js` 先求原图，再对每个假说分别禁止其事件序列并求解。使用相同地图、游戏资源、真实动作、无伤无复活目标。

| 原图 / 禁止条件后的结果 | 结论 |
| --- | --- |
| 原图有证书，禁止后穷尽且无解 | `necessary_within_scope`：此范围内每条通关解都含该事件序列 |
| 禁止后仍有证书 | `avoidable`：至少有一条绕过该序列的解 |
| 原图已证无解 | `base_unsat`：不能从原图无解推导机关必要 |
| 其余预算不足情形 | `unknown`：不生成必要性或无解标签 |

删除门、移动钥匙等是**另一张地图的对照实验**，不能替代原图禁止事件的证明。必要性只说明机制不能绕过；强迫玩家绕远路同样可能产生必要性，不代表设计精妙。

## 事件与历史

BFS 和 A* 都接受 `restrictions: [{ id, sequence: [...] }]`。每条 restriction 禁止一个**有序子序列**，事件之间可以有其他动作；多条 restriction 同时生效。分析器则逐条独立运行，以便分别判断假说。

- `visit`：成功动作后玩家位于指定 `layer/x/y`，不要求首次进入。
- `pickup_key`：本次成功动作使钥匙计数增加，跟随实际拾取，不依赖固定坐标。
- `press`：按下指定 `letter` 的按钮；按真实站位、方向及按钮数组优先顺序识别。
- `ghost_at`：成功动作后指定层格有任意鬼。
- `gate`：成功动作后指定 `layer/axis/x/y` 字母门处于指定 `state`。
- `all`：本次动作同时满足 `events` 中的全部条件。

初始态不产生事件；无效动作和死亡后继不产生可用轨迹。一次动作至多推进序列一项；需要同一步满足两件事时使用 `all`。例如“拿钥匙后再按 A”要求两个不同的成功动作。

监控器进度同时加入 BFS 完整状态键、A* 完整状态键与资源支配分组。否则两条到达相同物理状态的路径可能被错误合并，造成伪无解。成功证书还要在原引擎逐步检查禁止条件。现有事件不依赖体力、计步或迷雾知识，因此同监控进度下的资源支配仍成立；增加这类事件前必须重新论证，不能直接照搬剪枝。

## 新的受控单元

[互补开关与旁路对照](../examples/mechanism-lab/README.md) 采用新家族 `complementary-switch-v1`：一对同字母、相反初态的门，先开放钥匙支路，取得钥匙后返回切换，才能开放出口支路。

- 原题最短 `T=14, L=12`，至少两次按 A，且拿钥匙后必须再按 A。
- 只删除出口数字锁门，最短降至 4 步，整个开关机构均可绕过。
- 旧诱鬼题的探头、按按钮、先探头后按按钮，以及“门关闭且鬼在左侧”证据，已用通用分析器与独立 BFS 交叉复现。

这些是人工设计/受控对照，尚无真实偏好标签。原题和对照、全部编辑后代必须保持同一家族分组；两个旧诱鬼题仍属于另一个相同家族，不能随机拆入训练和测试两边。

## 自由编辑实验

`src/design/edits.js` 对单层 free 图支持活动格切换、任意墙类型替换、终点迁移、现有鬼迁移、钥匙增删、按钮增删。格子切换重置四边连通；删除实体占据的格子会被原图校验拒绝。按钮编辑按格增删，不是直接改变游戏过程中的门态。

`src/design/search.js` 用固定 uint32 随机种子选择父图和底层编辑，不套用固定谜题模板。当前不增加鬼数量，不扩展层数，提案的字母为 A/B、锁门门槛为 1；可以经直接编辑 API 指定其他合法墙数据。这是有限提案空间，不代表完整设计空间。

所有合法中间图均可作为父图，包括已证无解和未知图，以便越过暂时破坏可解性的编辑过程。无效编辑、重复图、失效的坐标条件分别记录；求解器内部故障会中止实验。保存：

- 规则提交、生成器/评价器版本、随机种子、预算、原图标识与家族。
- 每次提案及父图 ID、完整地图、父节点、编辑深度、完整求解与反事实证书。
- 已解图按“必要假说集合 × 动作数分桶”保存首个代表，仅用于多样性取样。
- `humanPreference: null`；没有人类偏好评分，不把未知填成负例。

这一档案**尚不是完整 MAP-Elites 质量搜索**：没有学得的质量奖励，也未检测迷雾公平性、可读性、装饰冗余、解法新颖性。出生点即终点等低价值地图也会如实记录，不能直接作为优质训练正例。地图哈希用于内容去重，并不识别旋转同构或游戏行为等价。

固定种子实验 96 次编辑得到 87 张不同后代：34 张有解、53 张已证无解、9 次重复；连同原图共 88 张，覆盖 7 个证据桶。详见 [实验摘要](../examples/mechanism-lab/search-summary.json)。这些数字不是好图率：例如有的变体只需按一次按钮，另一些把终点挪到出生点；系统应保留其退化证据，而不是奖励它。

完整本地运行保存在 `runs/design-20260929-v2.json`，被 Git 忽略。时间预算可能随机器负载改变未知状态和档案结果；同种子/版本的底层提案顺序和修改链固定，不能保证跨硬件耗时或预算结论完全相同。

## 使用

```text
npm run analyze -- examples/mechanism-lab/complementary-switch.json examples/mechanism-lab/analyze-config.json
npm run search:design -- examples/mechanism-lab/complementary-switch.json examples/mechanism-lab/search-config.json
npm run rebuild:mechanisms
```

需要保存完整运行时，在 search 命令最后传入一个新 JSON 文件路径；父目录须存在，已有文件不会覆盖。直接 `node src/design/cli.mjs search ...` 的标准输出为纯 JSON；npm 自己会添加横幅。

分析退出码：0 已解且所请求的反事实有结论，1 原图已证无解，3 有未知，2 输入/运行失败。搜索退出码 0 仅表示完成指定次数的实验，不能理解为找到了优质地图；具体标签看记录。

## 实际走法核对

~~~text
node scripts/inspect-puzzle.mjs examples/temporary-entry-20261020/map.json
node scripts/inspect-puzzle.mjs <地图.json> <明确动作数组.json> --json
~~~

工具支持本体当前的分层地图及本体仍接受的旧扁平格式，通过共同引擎装配，不另猜出生点或复制规则。第一条只看初态；第二条的动作文件必须直接是动作名称数组，如["U","R","STAIR"]。旧{map, solution:{solution:{actions:[...]}}}录制仍可直接读取，显式动作数组优先；不猜prefix、suffix或任意顶层actions的含义，不自动求解或调用试玩技能。

每层输出带坐标的文字图、完整元件和特殊边，鬼与钥匙叠放不互相掩盖，箭头按真实方向显示；层号和坐标从0起。逐步显示玩家与全部鬼的前后位置（含停顿）、按键、钥匙、真实字母／数字门变更及本体给出的争位记录。JSON同时给出首末物理局面，不能从门最终关闭推断鬼当步没有移动，也不能把所选参考写成全解唯一。

第一处无效动作、死亡或通关即停止，并列出未执行尾段。这里是无复活的物理核对：死亡保持共同引擎死亡局面，不是网页完成复活后的显示状态，也不模拟真人试玩。退出码0表示静态查看、有效未完前缀或完整通关；1为死亡；2为输入／动作无效或带有终局后未执行尾段。原图、原录制及反馈不写回。

## 自动提出稳定安排

`npm run analyze:arrangements -- <地图.json> <新的结果.json>` 从共同引擎完整可达图中提出安排条件，不读标题、参考解、设计说明或质量标签。结果文件必须不存在；退出码0为完成或原图已证无解，2为预算未知，1为输入／写入错误，具体看`status`。

安排包括各层无序鬼位、可变门状态、剩余物品、钥匙、生命，**以及玩家可来回活动的区域**。只经过相同鬼位不能算已安置；保持上述条件的真实行动需形成至少两个玩家位置的强连通区域。初态安排、鬼重合及终局不作候选；相同可见安排和玩家区域不按鬼编号拆分。

逐项禁止候选条件，区分`all_winning`（全部通关必要）、`optimal_only`（避开仍能通关但更长）和`avoidable`；`reduced`只描述必要安排的首次出现顺序，不禁止后来回访。预算不足返回`unknown`，不提供部分必要性结论；原图无解为`base_unsat`。默认25万状态、25万展开、60秒、3000候选，可通过`analyzeArrangements(map, options)`调整。

`createArrangementPredicate(env, report, id)`生成原图目标谓词，并核对地图和规则绑定；删门后的另一张地图必须重新分析。该分析要先穷尽原图，因此是设计核查线索，不能称求解前自主选目标或求解提速。安排数量、必要性和长解均不是趣味分。当前独立核验范围为单层开发地图；[实验与反例](archive/research/automatic-arrangements-20261016.md)保留。

## 完整普通计划反例

`npm run analyze:ordinary -- <地图.json> <新的结果.json> [预算.json]` 查询原图完整通关：每只鬼能否独立前置或收尾，以及各完整处理顺序。某方末次与另一方首次移动可在同一动作，处理阶段进入完整状态键；不会用严格禁止所有共同移动来制造伪交错。只支持单层，无伤无复活，默认排除经过非死亡重合的路线，终点当步另查去掉判胜是否死亡。鬼移动按本体实际记录计，去终点的反事实不写回实际轨迹。结果包含真实动作证书、各鬼首末移动步（不动为null）及其是否与本报告基线同长，避免把根本未动的角色误说成已经处理。原图、参考与反馈不改写。

默认每查询25万展开／状态、10秒，总计60秒，完整顺序最多24项；预算文件可调`nodeBudget`、`stateBudget`、`budgetMs`、`totalBudgetMs`、`orderBudget`与`avoidOverlap`。`avoidOverlap:false`明确放宽重合范围，不能将这种证书不加说明称为普通安全走法。`completeOrders`列出总顺序数、已查数及覆盖是否完整，未查完或超预算保留`unknown`，不能声称所有顺序无解；基线在同一限制范围已穷尽无解则跳过其子集。退出码0为所查结果有结论，2为有未知，1为输入／写入失败，已有结果拒绝覆盖。

这只是提前找熟悉办法的反例，不是趣味筛分器；连一条走廊中连续尾随的两只鬼也可能没有分段解，操作却完全无需思考。步数最短仅在报告的重合／去终点限制内成立，正式候选仍需独立的全部最优验收。不能用“没有普通替代”替代新的认识、合理选择和真人体验。

## 当前使用范围

这里的接口用于检验设计假说、寻找反例和有限编辑，不要求先生成大量题或按固定路线训练。设计前按[持续方法](methodology.md)写关键发现，当前资料数量与亲缘分组见[状态](status.md)。需要评审时只交付少量已内部审查的候选；参数训练是另一个可选阶段，不能把两个保守亲缘组或大量状态行当作独立质量数据。

### 一步物理影响与完整普通方案

`src/design/ghost-influence.js`只比较当前真实动作中，逐鬼移除其它鬼后的位置，并单列非致死重合。位移相同也可能两鬼汇入同格，不能当作干净的普通反例；终点的去判胜死亡检查另做，不能把该反事实记为实际互动。跨层时仅在当前克隆上临时唯一标记，先断言物理不变，不依赖地图的层内编号；若加来源历史，仍须进入完整状态键。`none`不证明整套方案独立或无思考价值，`motion`也不证明巧妙。完整普通顺序仍用上文`analyzeOrdinaryPlans`的明确范围；本工具不是另一套规则或趣味评分。
