## 先提出可以解释的矛盾

把上方死角由终点改为钥匙，另设需要两把钥匙的终点。这样冲入死角不再结束游戏，必须带着钥匙安全返回。再让临时保护与目标通路发生冲突：B 保护下鬼时也关闭上方入口，恢复入口会释放身旁的鬼；右 A 隔开上鬼后，也需要从另一站解除。突破应来自改鬼位、提前准备和保护交接。

这仍沿用之前的家族，只是待验证的结构提案，不是模型训练成果或全新机制。它是否难，需要人类试玩判断。

## 关系条件怎样排除捷径

在原图上禁止一个事件或有序子序列，再搜索是否仍有无伤胜利路线。有解说明关系可绕过；预算未知不能作必要性证据；穷尽无解才支持该条件不可跳过。所有六项均由快 A* 与直接调用固定原引擎的 BFS 独立复核。

| 禁止的事件或子序列 | 具体状态含义 | BFS 穷尽状态数 |
| --- | --- | --- |
| 临时 B 保护 | 按 B 当回合有鬼在 `(2,4)`，其上 `h[4][2]` 和左 `v[4][2]` 都闭合 | 6184 |
| 右 A 保护 | 玩家在 `(3,3)` 按 A，有鬼在 `(3,2)`，`h[3][3]` 关闭 | 2765 |
| 临时 B 后的 C 移位保护 | 上述临时 B 之后，玩家在 `(0,3)` 按 C，有鬼在 `(1,3)`，左门 `v[3][1]` 关闭 | 15944 |
| C 准备后左 A 释放 | 上述 C 事件之后，在 `(1,2)` 按 A，右门 `h[3][3]` 打开 | 21915 |
| 撤销先前右 A 保护 | 上述右 A 关闭之后，其保护墙再次变为 open | 13074 |
| 释放后由 B 接过保护 | 右 A 保护 → 左 A 重开 → 按 B 时有鬼在 `(1,5)`、`v[3][2]` 关闭 | 34740 |

这些条件把“困住一次、一路跑完”的图筛掉，要求临时状态为下一阶段作准备、先前的保护确实被撤销、别处重新承担保护。条件与完整结果在 [evaluate.mjs](../examples/borrowed-shelter-20261009/evaluate.mjs) 和 [evidence.json](../examples/borrowed-shelter-20261009/evidence.json)。

每项只证明某个事件或某对有序发生至少出现一次，不证明第一次动作就按该顺序，更不证明唯一完整按钮序列。`ghost_at` 指任一鬼；本证书的上、下鬼分工不能推广为所有解。源图诊断中，禁止“临时 B 早于右 A”仍有 73 动作解，禁止指定下鬼先后顺序也有 79 动作解，因此没有采用这些过强条件。这两个数来自源图，不是最终图的替代解长。

## 人类视角审查

查看真实全图后，重放三条人工提出的自然计划：直接取上钥匙于第 8 动作死亡；右 A 原站重开于第 12 动作死亡；没有转移下鬼就恢复 B 于第 29 动作死亡。保持两处暂时安全后直取上钥匙的计划被关闭入口挡住，但可用 46 动作后缀恢复。没有把一条直接计划失败说成该局面永久无解，也没有把假设路线当作用户行为。

本证书至少有临时隔开、把下鬼转到 C 内侧、解除上鬼原保护、让 B 完成最终交接四个相互影响的阶段。C 关门时右侧 B 仍开着，下鬼到最后一次 B 才完全围住；最终上鬼也不是四边全封闭。[解法与逐格作用](../examples/borrowed-shelter-20261009/design.md) 和 [计划审查](../examples/borrowed-shelter-20261009/strategy-review.json) 如实记录这些状态。

每个活动格已记录实际站位、视线、转角或保护用途；下方开放区域主要承担诱导几何，不能据此宣称每格都有独立认知贡献。C 小室可能仍明显提示围住用途，整题也可能被顺手试过。当前没有已校准的趣味函数，机械关系、最短长度和局部精简都不替代用户判断。
