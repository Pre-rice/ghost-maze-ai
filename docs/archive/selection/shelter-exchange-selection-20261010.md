# 《回环》的机制关系筛选

本文包含新题的机制剧透。试玩入口和无剧透产生过程见 [地图说明](../../../examples/shelter-exchange-20261010/README.md)。

## 从上一张题学到了什么

用户观看解法回放后认可的突破，是拉开距离，用走位把鬼引到提前关闭的 A 门下方。走位能布置鬼的位置；关门能为未来的布置准备条件。二者与另一只鬼的移位相互准备，才产生了超过普通追逐的推理。详见 [本次经验复盘](../reviews/borrowed-shelter-review-20261010.md)。这是回放后的设计正反馈，不写成无提示独立通关。

新提案由具体矛盾出发：当前保护安排虽然安全，却占用了完成后续任务所需的位置或通路。玩家要先构造另一项安全条件，再主动撤销已有保护。同一段空间应在前后阶段承担不同作用；不能只给每只鬼各加一个独立绕圈。

## 实际产生过程

探索保存于 `runs/position-relations-20261010`，没有训练模型。

最初尝试两个回路共用路口。b/c 轮出口封边不完整，编辑也可能覆盖封边，存在绕过钥匙的捷径；这些结果作废，不能计成有效候选或质量实验。修正后的 d 轮仍没有满意组合。

e/f 轮从上张正面图增加上方回路，出现了长解，但新增部分多为独立追逐，淘汰。g 轮加入第三只鬼，仍有类似问题。h 轮要求它提前参与，固定种子 `1010293` 的 5500 个提案只有索引 `4418` 进入审查。此时的母图仍有关系捷径，尚不够交付。

随后围绕母图作 60 个手工结构变体。选中的索引 0 删除右边重复 B 按钮，封住下钥匙室上下侧，只留 A 控制的侧口，才保住所需关系。最终源图保存在 [source.json](../../../examples/shelter-exchange-20261010/source.json)，来源索引与精简链保存在 [evidence.json](../../../examples/shelter-exchange-20261010/evidence.json)。

精简时曾有一版删掉上方内侧小回路，虽有 23 格，解却增长到 79 动作，局部走位退化为长距离追逐。因此没有采用。最终保留 `(1,1)` 小回路及互补 A 入口，再从 27 格精简到 23 格；294 次尝试，最终 74 项审计，未决 0。删掉四个外围格及三处冗余字母门属性。这是保留三鬼、两钥匙、小回路与指定关系条件下的精简，不是无条件局部最小或全局最小，也没有证明三只鬼分别不可删。

## 为什么要按关系筛选

只看“可解、解很长、按钮很多”，会把普通追逐留下。这里检查的是：一项操作改变了什么条件，这个条件是否为后续操作准备安全，后续操作又是否迫使先前的安排改变。

坐标从零开始。选中证书中的 B 临时保护位置是 `(2,4)`，C 停位是 `(1,3)`，另一处 B 停位是 `(2,2)`。事件不仅要求按按钮，还要求动作后有鬼处在指定位置、对应门处于指定状态，避免把无关按键算成安置。

具体限制定义见 [evaluate.mjs](../../../examples/shelter-exchange-20261010/evaluate.mjs)。对原图分别禁止以下事件或有序子序列，检查是否还能无伤、无复活通关：

| 禁止的关系 | 要排除的捷径 |
|---|---|
| 按 B 后，鬼在 `(2,4)` 且左侧 B 关闭 | 完全跳过临时保护，直接去完成目标 |
| 上述临时保护之后，按 C 且鬼在 `(1,3)`、左侧 C 关闭 | 保留第一次保护，跳过后续移位 |
| 临时保护 → C 停位 → 再次临时保护 | 使用一次就够，不必腾出并再次利用该位置 |
| 按 B 后，鬼在 `(2,2)` 且右侧 B 关闭 | 绕过另一处停位，与主线无关地处理上方鬼 |
| 按 B 开通 `(2,4)` 左侧门、鬼已到该格 → B 临时保护 | 省掉原地按键的诱导，单靠直接靠近完成全题 |

这五项均要求快 A* 与独立原引擎 BFS 穷尽无解。结果与完整预算写入 `evidence.json`；耗尽预算只能记 `unknown`。初次构建的一项检查耗尽预算，因此将快搜索时间预算调至 30 秒、原引擎调至 180 秒，并将每项结果排他保存，避免续跑时重复已经完成的证明。

这些结论证明对应事件或有序子序列不可省略，不证明唯一完整顺序。`ghost_at` 指任一鬼，不能据此说所有解都必须按选中证书的身份分工进行，也没有证明第一次与第二次使用该位置必为不同鬼。

## 选中证书里的相互准备

1. 先把左上鬼拉到 `(2,2)`，B 暂时隔开它，才方便进入后续 A/C 操作。
2. C 开出另一停位，A 打开下钥匙室；B 原地开门，让下鬼从 `(3,4)` 靠近到 `(2,4)`，随后切回 B，获得临时保护。
3. 下鬼不能一直留在那里。用下方走位把它移到 `(1,3)`，C 关其左侧，腾出原先的位置。
4. 再切 B 后能取下钥匙，同时撤销左上鬼原来的保护。先维持其停位，再从左列引出，把它带到已经腾出的 `(2,4)`，再次切 B。
5. 回到上钥匙的小回路，改变接近方向，引走初始上鬼，取得另一钥匙并去终点。

临时位置先服务下鬼，腾出后再服务左上鬼，是这条证书的用途转换。C 停位最终右侧 B 仍开着，`(2,4)` 也不是四边封死；安全来自鬼位、门态和视线的组合。初始上鬼最后仍会追随走位，不能说三只鬼都永久困住。

A 会联动下钥匙室与上钥匙的小回路，但没有证明 A 必须按两次，或必须在某个唯一阶段恢复。未精简结构的相应限制曾找到 71 动作替代解，这项要求没有纳入最终筛选。保留这个反例，避免把选中路线的做法误写成全局必要性。

## 人工审查与证据边界

[strategy-review.json](../../../examples/shelter-exchange-20261010/strategy-review.json)保留三条人工提出的常规计划：从右直取上钥匙、沿左列直取上钥匙、开 A 并用 B 拉下鬼后立即进室取钥匙。它们经原引擎重放检查，不能当作观察到的用户行为，也不能推广为所有直觉策略必败。

23 个活动格逐一记录空间用途。上方的小回路让最后取钥匙保持局部操作，下方两列承担拉开距离、切换视线及移交；两处停位和三处按钮关联前后阶段。没有发现纯通行格，但这不等于每格都有独立的认知必要性。上钥匙末段仍含追逐，整题是否比之前更巧妙，要等真实试玩反馈。

原图无玻璃，因此玻璃替换实墙后地图恒等，全部策略保持不变。A/B 向上依附实墙，C 向左依附边界墙，源图、最终图与分享码解码结果均检查依附。默认体力 100，最短 70 成功动作：61 移动、9 按钮，体力剩余 39。

原引擎、快实现与分享码逐动作物理及探索状态核对；反序鬼数组后证书仍胜利，移除终点后仍安全。独立浏览器 QA 与正式试玩分开，测试录制只进入 `runs/shelter-exchange-20261010/qa-recordings`；验收详情见 [browser-qa.json](../../../examples/shelter-exchange-20261010/browser-qa.json)。这些检查不构成迷雾知识策略证明。

本题继承 `dual-loop-relay-v1` 拆分组，不作独立泛化成绩，生成时 `humanQuality:null`。下一步分析用户实际卡点及走位，检查是否需要重理解安全安排，还是仍能局部试探后顺手完成。
