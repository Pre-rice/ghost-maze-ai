# 暂留研究：无字母通路与追逐空间

2026-10-17。承接《互锁》未感新意的实际反馈，暂停交替控制位／控制移交的相似交付。以下原型没有交付，不继承《互锁》的评价，也未入地图集或质量训练资料。

## 实际结果与没有采用的理由

| 构造 | 结果 | 取舍 |
| --- | --- | --- |
| 四个小区与一次性门 | 首批81份因0紧邻守卫而全部无解；修正批81份中71可解、10无解 | 严格先后搬运限制也排除了同时移动，不能据此宣布关系新颖。代表图左钥匙先取24步、右先取20步均可解，先后不是全解必要 |
| 放大成两间长房 | 324份中194找到解、130预算未知；194份中183有逐只处理证书、11限制仍未知 | 增加空间使钥匙能独立先拿，削弱原约束。未知不当困难或无解；没有找到已证明的双向交织 |
| 收紧回程出口 | 四稿均22步；实际13步安全计划拿齐钥匙后穷尽无续解 | 仍有普通继续追逐的通关计划。相同鬼位和资源，玩家已在外面却有32步反例；只有玩家仍在右下区的安排才无后路，不能省略玩家区域 |
| 开阔空间分开追逐队列 | 16步，优先占位对全部无伤通关必要 | 沿外围绕行就会自然触发，不需主动建立不同理解，作为机制构件保留 |
| 给上述空间加隔断 | 四稿中三稿全部最优边界被鬼重合拒绝，另一个变14步且优先不再必要 | 加墙不自动增加深度；不改规则给图放行 |
| 增加第三鬼守共享回程 | 目标旁路稿20步；封旁路后32步 | 前者没有处理预想矛盾，后者参考路线中第三鬼从未移动，仍近似分段处理，不交付 |

代表性查询在归档位置重新执行，保留原先过强监控的通关反例与收紧范围后的穷尽结果。原脚本、预算未知、死图、边界拒绝及修正均另存，不只保留成功叙述。私人原件与新包索引见[清单](../../../data/manifests/no-letter-spatial-20261017.json)。

## 这轮阅读怎样用于后续

读了两篇开发者访谈：Alan Hazelden团队谈[《A Monster’s Expedition》的构造过程](https://www.gamedeveloper.com/game-platforms/the-relaxing-open-world-puzzle-design-of-i-a-monster-s-expedition-i-)；Patrick Traynor谈[《Patrick’s Parabox》的规则与迭代](https://www.gamedeveloper.com/design/patrick-s-parabox-)。没有观看收费演讲，也不保存文章全文。

前者从一项具体交互及玩家预期反推布局，再主动找别的完整方案；一组变体也可能全被剪掉。这提醒我，下一稿应先展示“眼前合理计划为何不足”，不能搜索后把必要事件包装成思想。后者强调自然、直觉、便于推理的规则，并主动避开少数别扭行为；与本项目排除鬼重合和玻璃差异的边界相符。其偏好简单顺畅关卡，不代表当前用户也要更简单，不能借此降低本项目挑战目标。

这些只是设计者的理解，不是新的用户反馈，也不证明阅读已提高作品质量。下一原型从具体矛盾反推：要安置的鬼起初占着创建出口所需的格子，先腾空才可能建立最终通路。先查普通替代是否仍成立，再决定是否值得继续；不以面积、必要性或数量替代试玩价值。
