# 控制位置与返回通路

2026-10-17。承接《送客》被否定的真实反馈，停止在既有双环母图上收束相似交付；本轮结果为待试玩[《互锁》](../../../examples/control-room-interlock-20261017/README.md)，没有更改十五张地图集或训练模型。

## 从假说到取舍

起点是“单向离开后，同组开关的另一操作面能否承担新的作用”。首稿无解；有限功能替代找到一个32步、两处操作面均必要的版本。原先希望出现的双鬼优先交接并未实现，不能继续沿用该解释。进一步去掉0门、改出生与中央通路后，仍只是各用一次的控制段。

随后改为“为回到控制位置，必须先撤销眼前已经完成的开路”。第一稿整体无解；移动终点前门后又产生只按右侧或只按上侧一次的捷径。封住上侧旁路、把下侧普通门改为右向单向门，才排除这些实际替代，得到36步的至少三个控制位置段。再将上方字母门换普通门，省两步且保留关系，采用34步稿。这里改变了原先解释：第一次上A是打开自己的出口，不必保留旧的关门困鬼动作。

当前4×5图全部最优无重合、去终点安全、冷初态与指定实际入场通过；两鬼各自删去都有10／12步普通捷径。至少上→右→上三个位置段是原图全部无伤无复活通关的限制，历史进入完整状态键，允许非最优非致死重合。重复按同一处不能冒充换面。

## 删除、移动与反例

- 四扇A门、两个单向门及两个普通门均核对普通替代，不能只看解长：原路线可能仍通关，但改图出现更短且绕过核心的方案。上侧入口A可改普通门，因此不为保留旧解释而留着。
- 删除顶右角或终点右侧三格分别仍34步，且至少三个位置段不变；保留完整轮廓。其他合法非元件格单删均无解。上按钮左移出现22步两段捷径；右按钮上下移不省步。
- 实际安全前缀“上、右、右、按上A”后穷尽续解无解。但另一条较长的提前操作仍可恢复，不能泛称“所有提前按A都无解”。
- 第二处A多按一次可以继续按回恢复，不能记成不可逆死局。需要区分少一次控制位置切换，与临时多按几次。
- 原型右下角有两处边界误留为空，不符合设计边界要求，不能凭引擎校验与原型QA放行。当前稿从元件表重新构造显式实墙，重新通过全部验收，四条最优动作与鬼轨迹保持；问题原型、旧编号和原证据保留隔离。当前来源不冒用原图身份。

## 证据修正与范围

首个32步研究的“取物后引动守卫”曾监控到旧角色，不能用作预想交接证据；当前公开证明只监控实际门态、按钮位置与完整历史。早期对象型历史因不满足搜索接口而报错，没有得到证明；更早的整体无解原型，其禁按钮也无解是空命题，不算必要性。

本轮`interlock-structure`试验中`avoidRightParkingBeforeFar`误以所有A按键数判断“尚未按右方”，实际上没有禁止第二次A，结果无效；该原件保存，不进入公开证书。`firstUpperWithoutLeftPark`找到50步恢复方案，所以只在最佳路线描述左鬼先停左侧，不能推广成首次操作的全通关必要条件。公开验证脚本独立重算四项控制限制，未使用这些错误角色监控。

程序能排除捷径、冗余和虚假的解释，不能证明顿悟。当前交付理由仅为它提出了与被否决作品不同的控制关系，并已经过精简后复审；没有真人体验、评分、用时或AI盲测。亲缘组保守合并，不把这次构造当独立训练家族。
