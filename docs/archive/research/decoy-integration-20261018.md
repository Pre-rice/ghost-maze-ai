2026-10-18。本文件只存在于 `experiment/one-shot-passage` 分支。它描述“如果要把 `DROP` 提升为正式规则，需要动哪些地方”，不是已执行的改动。

## 二、兼容性

- **动作码扩展会改变现有回放协议的位宽/字典**：老回放必须仍能解码。建议用“版本号 + 新动作码段”的方式，老版本保持原编码。
- **状态键扩展**：现有地图的 `mapId` 不变（地图内容哈希），但求解器缓存/训练数据的键会变，需要重建或按版本隔离。
- **现有地图**：由于玩家可以不用 `DROP`，现有地图的“无伤通关”仍然成立；但“全部最优”的定义会变（最优解可以选择不放标记）。若要保持现有证书原样，建议只在新规则地图上启用 `DROP`，老地图锁定旧协议。

## 三、网站改动

| 位置 | 改动 |
| --- | --- |
| 输入处理 | 新增“放置标记”键位（建议 `Space` 或 `E`） |
| 渲染 | 标记画成半透明圆点，与鬼、门区分 |
| 帮助弹窗 | 增加一条规则说明（一句话：鬼看不见你时会走向最近的标记） |
| 求解/提示 | 若网站提供“提示”，需要让求解器支持 `DROP` |
| 回放 | 回放控件显示 `DROP` 图标与次数 |

## 四、工作量估计

- 引擎：1-2 天（含状态键、回放协议、测试）
- 网站：1 天（输入、渲染、帮助、回放）
- 求解器：0.5 天（BFS 增加动作即可）
- 验证：现有 `npm test` + 新增诱饵地图的 verify

## 五、风险与替代

- **风险一**：回放协议版本化可能影响历史录制。缓解：老地图锁定旧协议，新地图用新协议。
- **风险二**：`DROP` 可能让某些现有地图出现更短解。缓解：现有地图禁用 `DROP`（按规则版本区分）。
- **替代方案**：如果不想动协议，可以把 `DROP` 做成“编辑器专属机关”（地图里预置标记，玩家不能主动放）。这样不需要新动作，但谜题会变成“预置诱饵”的一次性设计，失去“放几次、放哪里”的规划深度。**不推荐**。

## 六、当前可验证的原型

分支里已有三个可复验原型（都依赖 `src/experiments/decoy-environment.js`，不改本体）：

- `examples/decoy-20261018/`（10 格、10 步、两次标记）
- `examples/decoy-unique-20261018/`（17 格、13 步、唯一解、一次标记）
- `examples/decoy-challenge-20261018/`（28 格、28 步、四次标记）

每个目录都有 `verify.mjs`，`node examples/<dir>/verify.mjs` 可直接复算。
