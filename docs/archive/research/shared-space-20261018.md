# 共享空间研究：有多次往返，仍可逐个处理

2026-10-18。《寄存》实际负反馈之后，设计者检验内外房间及四室配对，未交付新候选。没有新增真人评价、入集或训练；原件见[冻结清单](../../../data/manifests/shared-space-20261018.json)。

## 哪些预想没有成立

共享内室的普通门会把外鬼留在门口，原设想是让本次安全进出影响下一次入口。三乘二内室却能一次完成取物，旧视线的一步追击使手算中的停车失效。改成树形内室后，虽能证明至少三次进入，仍有先安置外鬼、再独立处理内鬼的37步无伤方案；原外鬼配置甚至能在完全不动的情况下沿相同31步路线通关。多次访问不等于两部分互相准备。

只有两口的直廊能迫使取物时原路退出，但双外鬼代表穷尽无解，连钥匙都无法取得。只剩一只外鬼时可以绕另一侧完成，另一鬼也可能全程不动。固定该三鬼布局，将一条外部空边改为0门的30种对照均穷尽无解，没有预算未知；此结果只否定所检构造，不否定“最后一次访问可放弃退路”的一般想法。

五乘五双圈的无按钮原型没有安全入室动作：四个中点端口邻近守卫，外围16个状态穷尽后即无解。不能把打不开的空间当成思考难度；未扩展为大规模布局搜索。

## 四室配对仍出现普通办法

四扇A门在左右配对和上下配对间切换，原本希望不能分别保留每次保护。但最初控制位没有给追逐留一步，六个代表均无解；无右上鬼时可解的诊断显示，问题在操作位。添加安全台后虽有40步解，却可先独立处理右上。加入下方守卫的44步最优还利用了非死亡重合，拒绝。

后续改变控制房和目标房，48步稿仍可先处理下方再独立处理上方。三控制45步稿所加的按钮附墙反而挡住了原守卫视线，该鬼全程未动；这不是实现了预期的相互安排。去掉附墙并按真实旧视线修正停车后的51步稿，仍能先把两鬼分别送到右上安全位置，再取钥匙、去终点；禁止任一鬼在取钥匙后移动，均存在同一51步最优。不能以三处控制、房间配对或流程更长来称整体规划已经成立。

## 留下的审查方法与限制

先检查一条完整普通方案是否能把某鬼永久处理完、之后只走目标流程；其次再审参考中的事件必要性。多个按钮共用字母、需要三次入场、两鬼都移动，均不足以排除独立处理。实际加入的墙也可能破坏原本的视线假设，叙述中的作用必须从引擎逐步结果核对。

这些稿只完成各自已记录的原生求解、部分最优重合边界及参考去终点检查，未做全部分享往返、实际入场和编号穷尽QA。没有公开试玩码或地图名，也没有把必要性诊断当作人的难度或新意评价。下一步离开本批操作台与逐个安置构造，不继续以加门延长流程递补交付。
