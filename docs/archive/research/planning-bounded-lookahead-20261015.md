# 给定停位目标：有限后路检查

2026-10-15。紧接[固定资料监督对照](planning-recovery-objectives-20261015.md)，不训练新模型、不生成地图、不改网站或精品图。本轮检验多步展开的贡献，避免把搜索收益写成模型突然学会了规划。

## 依据与做法

旧模型在精品15个必须腾位目标的45次失败中，全进入了不可恢复局面。按第一次进入死路后的可达闭包计，35次只需不超过8次展开即可证明目标不可达；37次不超过64，其余8次要733–772次。这是事后诊断，不作为策略输入。

在每次实际选择之前，从候选后继展开真实安全动作；找到给定目标就记可达，穷尽且没目标才记不可达，预算耗尽保留未知。只有已证明不可达的动作才排除。缓存按任务的可见物理局面保存，未知不升级为无解，不读取精确距离、任务种类、身份或证书。目标是明确给定的两格停鬼，不是游戏终点，也不是让模型自主选目标。

固定每个候选0／8／64次展开、每个任务总计最多4096次、最多256步。所有排序使用同样预算上限、原生无伤无重合过滤、规范局面重访回避和当步完成目标优先。模型使用上阶段原动作分类三份权重；对照是原手工进度与随机排序。它们不一定花掉相同的实际展开量，不能据任务数比较运行速度。

穷尽图只作为已经原生核验的转移缓存，推演仅查询当前实际展开节点的后继，不查询未来距离或全图可达性标签。下表是离线规划能力，不是实际原生求解耗时；尚未把这套循环接到实时引擎进行成本测量。零展开266条路线与旧结果完全相同，避免更换控制器造成假收益。

模型8预算每份实际合计展开19131／19187／20199，手工11958，随机13229／16444／18009。不能把完成数量的提高直接称更快。模型8预算的剩余失败中，前两种子各12个已进大死路，第三种子9个进死路、2个仍可达却在步数预算内未完成；小范围检查没有解决全部长期条件规划。

全部798条成功／失败前缀、71276个动作已在共同引擎逐步重放，通过给定目标、最优统计、无伤无重合及角色审查。563种不同任务路线、13母图，不是798张新图。重复合计370次完成／47次最优不是某一个模型的成功率。[完整公开摘要](../../../data/manifests/planning-bounded-lookahead-20261015.json)保留所有预算与全部对照，私人runs保存模型来源、原路线、失败和事后闭包审计。

## 判断与实际缺口

有限后路检查对三类排序都有帮助，证明搜索贡献实质存在；学习排序在当前小预算开发任务上有额外收益，但仍没有模型最优解，且这些目标属于已反复使用的精品开发资料。不能宣称独立泛化、完整游戏通关、自主目标选择或精品生成，更没有获得人类尤里卡体验证据。模型与这套策略都不接入网站，现有最优求解不变。

此前只换单步监督不足；现在小范围规划带来明确完成率改善，因此下一步优先复用展开过的规划图、让未知检查能继续，而不是加大每个动作的重复检查或再凑随机练习。仍须与相同预算的手工／随机完整规划比较，并实测原生成本。到给定目标的安排稳定后，再研究目标选择和组合，不能提前宣称已能生成精品。

9项Python回归通过，包括未知／无解区分、闭环穷尽、不能读取未来／身份、全局预算与预算末步成功；两仓统一检查通过。本轮网站资源仍与批准预览的56份哈希相同。
