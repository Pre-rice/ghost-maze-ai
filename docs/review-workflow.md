# 成对试玩与本地反馈

> 2026-10-11 当前边界：反馈工具使用共同本体规则；原六图包与原反馈保留为历史证据，其中两张跨层图的全局楼梯和层内空楼梯表冲突，严格校验下不能直接重建。不要重跑下文旧 builder 覆盖原图。当前合法题目和回放统一见[地图总目录](../../ghost-maze/docs/ai-map-catalog.md)；回放不再使用独立录制页。以下批次说明和验收数字属于原实验。

当前构建接口 `buildPacket(seed, groups)` 可显式传入合法地图组，每组为 `[familyId, A地图文件, B地图文件]`，文件为仓库相对路径或 file URL。它先校验原始资料，再求解和生成新码；默认旧六图组会明确报出楼梯冲突。新包另存后，通过 `startReviewServer({ packetFile, feedbackFile, recordingsDir })` 提供；不能覆盖原包或混写原反馈。测试仅在系统临时目录制作合法样例和试玩包。

2026-09-29：第一批 3 组、6 张地图已具备浏览器试玩、持久化反馈与导出入口。没有自动填写任何真实人类偏好，也没有开始训练。

## 信号范围

采用用户已选定的少量成对比较。显式选择、试玩情况和解答接触情况分别记录，避免从点击或通关推断喜欢；这种区分与 [Langfuse 用户反馈指南](https://langfuse.com/guides/user-feedback-loop) 的显式/隐式信号原则一致。当前完全本地实现，没有接入外部 AI 服务或上传数据。

| 优先级 | 状态 | 信号 | 含义与限制 | 工作量 / 实现 |
| --- | --- | --- | --- | --- |
| P0 | 已实现 | `choice` | A、B、平局、无法判断；表示这一组中的相对选择，不是绝对质量 | S / 本地表单与追加日志 |
| P0 | 已实现 | `reason` | 用户自己的理由，可为空；不自动改写成模型标签 | XS / 文本字段 |
| P0 | 已实现 | `playedA/playedB` | 自述未玩、尝试过或通关；不是自动验证的实际通关记录 | S / 表单与校验 |
| P0 | 已实现 | `priorExposure` | 自述未接触、部分接触、全知道、不确定；用于区分首次体验 | XS / 表单与导出标记 |
| P1 | 未实现 | 实际动作轨迹与死亡记录 | 可帮助解释卡点，但不能直接推断好玩；需要会话与轨迹绑定 | M / 后续游戏会话采集 |

除“无法判断”外，比较要求两题至少尝试过。允许未通关的比较，因为难以理解或执行本身也可能影响体验；导出保留试玩情况供分析时筛选。

## 地图与试卷绑定

`scripts/build-review.mjs` 对 6 张源地图重新求解，用原引擎重放分享码解码后的地图，并核对终局物理状态。随后将地图内容 ID、游戏提交、家族、分享码与固定种子分配的 A/B 侧序写入 `examples/review-batch-01/packet.json`。

`packet.id` 为整份内容的 SHA256，包含规则版本、侧序和分享码。保存请求必须带该标识及有效 pairId；地图或侧序变化会得到新标识及独立反馈文件。真实反馈中的地图 ID 和家族由服务端绑定，客户端不能提交或替换这些字段。

评审投影仅包含组号及 A/B 分享码，不发送来源、家族、求解成本、证书和反事实结论。服务只开放评审资源和同级本体静态文件，不提供原始例题目录。导出记录会包含地图标识和家族，属于用户主动导出的研究数据。这是界面去提示，不是保密机制：分享码本身可在编辑器中查看，已在聊天中见过的题也不会变成首次体验。

第一批来自三个家族：诱鬼环路、互补开关、跨层接力。每组两题共享家族；后代必须一起划分训练/验证集合。三个小家族只能用于校准流程，不能据此声称质量模型具备泛化能力。固定侧序便于恢复，当前没有多评审者交叉平衡设计。

## 记录语义

- 选择保存后追加一行 JSONL，包含事件 ID、时间、规则、地图绑定、原始表单与被替代事件 ID。
- 同一事件的网络重试返回原记录，不增加样本；同事件 ID 对应不同内容会报错。
- 改评产生新事件，并保留旧事件。每组导出最新结果；后来改为“无法判断”会从当前偏好比较中移除该组，历史仍保留。
- `preferenceForA`：A 更好为 1，B 更好为 0，平局为 0.5；无法判断不进入 `comparisons`。
- `firstExposure` 仅在用户选择“两题都不了解”时为 true；原始接触情况保留在 `records`。不能把其他值统一解释为“肯定看过解答”。
- 未保存草稿只在浏览器 localStorage 中，按试玩包与组隔离，不算人类标签。

本版为单进程、单评审者工作流；不提供多用户身份或多进程日志锁。损坏的日志、错误规则或地图绑定会拒绝载入，不静默修复或覆盖。`data/feedback/` 被 Git 忽略；导出后自行备份，后续训练只能显式使用真实反馈目录或用户确认的导出，不扫描 `runs/` 中的测试记录。

## 运行与验证

```text
npm run rebuild:vertical
npm run review:build
npm run review
```

前两个命令重写脚本生成的示例/试玩包，日常试玩只需要最后一个。服务绑定 `127.0.0.1`；POST 限制同源 JSON，限制请求大小，并拒绝额外标签字段。原游戏文件不修改，只在 HTTP 响应中将 CDN pako 地址替换为本地已安装的 pako 3.0.1；本地完整往返与六图通关均已实测。

验证结果：

- `npm test` 共 **90 项通过**（54 项参考/设计/评审测试、36 项旧套件）。
- 跨层题的 12 / 9 次动作及反事实三态，经独立 BFS 与 A* 对照。
- 浏览器使用真实方向键/空格，无伤通关全部 6 张地图，模式均为死亡循环。
- 浏览器表单保存、改评、刷新恢复、分组草稿与导出已验证；测试服务使用独立端口和 `runs/browser-feedback-qa-20260929.jsonl`，未向真实反馈目录写测试标签。
- 桌面与 390 像素宽度截图检查通过，手机宽度无横向溢出；截图位于忽略目录 `runs/review-desktop.png`、`runs/review-mobile.png`。
- 固定引擎、旧种子重放与原仓库状态检查通过，未修改子模块或原游戏。

后续先分析真实比较与理由，再扩大有差异的机制家族。数据积累前不训练偏好模型，也不将这些受控简单题冒称高可玩性生成成果。
